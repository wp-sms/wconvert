# Editor UX: implementation plan (prototype approved)

Approved prototype: https://claude.ai/artifact/UxPKfxD33noNgrbt7shnHv

## Context

A UX review of the campaign editor found that the merchant's everyday jobs pay for rare quiz features:
- **Words and look:** the same words are editable in three places, and clicking an element stacks seven panel layers.
- **Fresh setups start broken:** the recommended setup opens with "3 to fix", and two different issue counts disagree.
- **Copy:** labels are technical ("Quiet text", "Everyone else", "Save point", "Under AA").
- **Simple popups carry quiz controls:** Flow, Next screen and paths show even on a two-screen popup.

**Target state**
- **Tabs:** Edit · Display rules · Destinations.
- **Edit layout:** a left tree (pinned **Look** row, then screens that expand into their elements), the canvas, and one side panel. The panel is the Look panel, a slim screen panel, or an element panel (`← Screen` · name · Content | Style).
- **Flow:** appears only when there's more than one way through.
- **One Preview button**, with its modes inside.
- **Fresh setups open clean**, and one issue list feeds every count.
- **Plain words throughout:** one word list, a plain style panel, and the exact values under Advanced.

**Decisions**

| | Decision |
|---|---|
| D1 | Merge Screens and Design into one Edit tab. |
| D2 | When an element is selected, the panel shows that element only. |
| D3 | Leads default to "Keep in WConvert only" until a service is connected. |
| D4 | No modes. Features appear where they apply, and Flow appears only for multi-path campaigns. |
| D5 | The left tree has a pinned Look row. |
| D6 | One word list. |
| D7 | Plain style controls; exact values under Advanced. |
| D8 | One PR per phase. |
| D9 | **Lead magnet:** "Keep in WConvert only" satisfies the goal. Review shows a non-blocking warning that visitors get no file until a delivery email is set up. |
| D10 | **Offer links:** prefill the WooCommerce shop page (or the home page). Review shows a soft "Check where 'X' goes" line. An address the merchant clears still blocks. |
| D11 | **Result links are optional.** A result with no address hides its button and shows a soft hint. |

**Constraints**
- No database changes. New state lives inside the optin's existing `config` JSON.
- Branch, PR and merge only once `CI / Required checks` is green. Never push to `main`.
- `/mattpocock-skills:tdd` at behaviour seams and `/mattpocock-skills:code-review` before each merge.

## Phase 0: bugs, clean start, one issue count
Branch `feat/editor-clean-start`.

### Bugs (§10)
1. **Button action written directly.** Stop drawing `button.action` in `SlotFields.tsx`, so the swap menu (`structure/swap.ts` `withSwapped`) is the only way to change it. Drop the "Button action" param from the inspector settings.
2. **"Where the button goes" on non-link buttons.** Draw `href` only when `action === 'link'`. Submit, next, back, skip and close buttons get a one-line explanation instead ("Sends the form…", "Skips this form without saving…", "Goes to the next screen…").
3. **Empty link becomes the privacy policy.** `withPolicyLink` (`builder/policy.ts`) and `src/Template/PolicyLink.php` apply only to `consent` nodes and `text` nodes with role `fine_print`. A body-text link with no address becomes a blocker: "Add a web address for 'x'". The "leave empty for your privacy policy" hints show only on those slots. Update `PolicyLinkTest.php` and `builder-preview.test.tsx`.
4. **Review links open the design library.** The "Position" and "Reopen button" links (`ReadinessDialog.tsx`) get a new `onGoToLook` callback that opens the Look/settings panel, not the library.
5. **Copy points at UI that doesn't exist.** `JourneyEditor.tsx`: "Screen visibility" becomes the real section name; hide the "Next screen" pointer on Free.
6. **Dead state.** Delete `previewing` from `OptinBuilder.tsx`.

### Clean start (R4, D3, D9–D11)
- **Leads default to local (D3).** A missing `capture_mode` means `local` everywhere (admin and server). Choosing a destination writes `connected`; removing the last one writes `local`. Show `CaptureModeChoice` for every goal whose design captures a lead. Delete `keepLocallyUntilConnected` (`GoalScreen.tsx`).
- **Per-signup rule visible in the admin.** Mirror the server-only rule (`OptinController.php`) so the review never shows "ready" for a campaign the server refuses. Fix the stale "Collect only" wording.
- **Lead magnet (D9).** Local mode returns no blocker. New warning (not a blocker): "Visitors won't get the file until you set up the delivery email", opening Destinations.
- **Offer links (D10).** `src/Playbook/Prefill.php`: fill every `button` with `action: link` and an empty `href` with `wc_get_page_permalink('shop')` when WooCommerce is active, otherwise `home_url('/')`. Also replace the three Pro sample hrefs. Record those node ids in `config.unchecked_links`; editing that href removes it. Review lists "Check where 'Shop the sale' goes (now: Shop page)" as non-blocking. Skip `recover_cart` designs.
- **Results (D11).** Drop the `result-link` blocker. The renderer hides a result button with no `href`. `ResultSettings` shows the soft hint "Add a link to send visitors to the guide".
- **Phone country.** When Settings has no default country, use the region from `get_locale()`. The admin `phoneDefaultCountry` and the server check read that one value.
- **Allowed exception.** Cart-recovery recommend-accessory and add-useful-extras keep "Choose the main product" as a blocker.

### One issue count
- New `builder/readiness/campaignIssues.ts`, extracted from `ReadinessDialog.tsx`, returns one tagged list: `{said, tab, screenId?, path?, blocks}`.
- The header "n to fix", the per-screen warnings, the Flow badges and the review dialog all read it.
- Remove the separate "Issues (n)" button (`JourneyEditor.tsx`).

### Tests and safety net
- New PHPUnit test: every bundled playbook (Free and Pro) through `Prefill` and the publish validation; zero blockers except the listed exception.
- Matching vitest test for `campaignIssues`.
- TDD for `campaignIssues`, the capture-mode default, the policy-link scope and the prefill links.

### ADR
- **0133** "A fresh setup has nothing to fix". Amend inline: 0085 and 0132 (capture_mode default, lead magnet rule) and 0088 (review leads).

## Phase 2: one Edit tab (D1, D4, D5)
Branch `feat/editor-edit-tab`.

- `TabId = 'edit'|'rules'|'destinations'`; the Design tab goes; `BlockedTab` journey/design become edit.
- `lookOpen` focus beside `selection`: Look when open, the element when `selection.path.length > 1`, the screen otherwise. Clicking the empty stage opens Look.
- New `builder/EditTree.tsx`: pinned Look row; screen rows (kind icon, "Only if …", warning count from `campaignIssues`); the current screen expands into a nested `BlockTree`. Extract StructureView ops into `useBlockEdits()` and delete `StructureView.tsx`. Extra rows "Reopen button" and "Locked content preview" replace `ScreenControls`. "+ Add screen" menu: Message · Form · Question (Pro) · Offer · Optional signup; the Free 7-screen cap stays. Compact (≤1000px): tree becomes a drawer; panes "Screens · Preview · Edit".
- Canvas bar: Canvas | Flow switch only when `hasManyWaysThrough(tree)` (TDD, in `structure/journey.ts`); hint "Click anything on the <format> to edit it"; one `DeviceControls`, "Fit · N%"; Fullscreen.
- Look panel (`DesignSettings.tsx`): ready-made looks; colors; fonts; format and position; reopen button; use my theme's colors; "Browse designs and formats"; Advanced. Inline/content-lock show "Where on the page: <summary> · Edit in Display rules".
- New `builder/ScreenPanel.tsx`: header, this screen's issues, **Then →** (read-only on Free/linear; select on Pro, `upgradeToGraph` for linear), Form section, "When submitted · Save the lead", "Where leads go", first-screen "When it opens", **Show only if…** (Pro, not first screen), result settings, element chips. Removed: slot fields, "What happens to answers here?", "Next: …", "Open Design", `contextEditors`, `JourneySample` in edit view.
- Question element panel: `QuestionSettings` plus "Where visitors go next" hosting `GraphRouteSettings` ("Send some answers down another path", per-choice "Goes to"), "+ Follow-up question".
- Header: goal under the name (opens `ChangeGoalDialog`); one Preview button with As a visitor · This screen · Test a visit (moved from Display rules) · Try answers. "Preview & test" and "Check the design" go away.
- ADR 0134 "One Edit tab: look, screen, element"; amend 0131 §5, 0039, 0065, 0067, 0107, 0108.
- Tests: builder-shell, journey-editor, new edit-tree, screen-panel, has-many-ways-through; update navigator, design-tab, structure-view, readiness-dialog; visual suites inline/reopen.

## Phase 3: plain style panel and Flow map
Branch `feat/editor-style-flow`.

- One size control per text kind ("Size": Small · Medium · Large · Extra large, plus Custom); heading-size tokens and heading rank under Advanced.
- One `Advanced` disclosure in ScopeStyle and Tokens holding units, px fields, degrees, %, typed values, custom CSS and hex inputs; the plain view keeps presets and swatches.
- Color names via `colorName()`; hex under Advanced.
- One `readability()` in `contrast.ts`: "Easy to read" / "Hard to read on this background…" with **Fix**; ratio only under Advanced.
- Reset this element (per device).
- Flow map: opens fitted; toolbar − % + · Fit · Tidy up · Highlight paths · ⋯; issue marker popover from `campaignIssues`; one-time drag note.
- A hidden screen continues to the next screen in display order (TDD on traversal; Pro renderer and server); the `hidden` edge stays an optional override.
- ADR 0135; amend 0054, 0078, 0084.

## Scenario and template matrix

| Scenario | Representative setups | Must hold |
|---|---|---|
| Floating bar / offer | `bar-announcement`, `bar-countdown`; `promote_offer` | One screen, "+ Add screen". No Flow, no "Then". Link prefilled with a soft check. |
| Email popup | "Welcome discount", grow_email_list | "Then → Thank you". Form line. Leads local. 0 blockers. |
| SMS / phone popup | drop-alerts, service-text-updates, vip-early-access | Phone country from locale. 0 blockers. |
| Popup + optional signup | journey-email-then-sms, headlines-optional-sms | Each form has "Where leads go". Server and admin agree. No Flow. |
| Lead magnet | 16 + Pro fullscreen-guide | Publishes local, non-blocking delivery warning. |
| Enquiry | journey-enquiry, landscaping-enquiry | Straight line, no Flow. |
| Slide-in / fullscreen | Pro display-types | Look position options per format. |
| Inline / content lock | inline playbooks, content lock | Look shows placement summary; "Locked content preview" row. |
| Reopen button | popup with reopen | Tree row "Reopen button"; review link opens Look. |
| Quiz (straight) | project-stage-finder, service-finder | Question panel, "Then →", no Flow until a path is added. |
| Quiz with paths / results | content-guide, gift-finder, product-finder | Flow switch, fitted map, result links optional, 0 blockers. |
| Cart recovery (Elite) | shopping-guidance; recommend-accessory | Clean; the "Choose the main product" exception. |
| Free install | any on free only | No Question/Flow/path UI; Pro lock in Add screen. |
