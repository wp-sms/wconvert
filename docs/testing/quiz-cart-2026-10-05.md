# Quiz cart actions and product activity — 5 October 2026

## Implemented

- Each quiz result offers View product (default) or Add to cart.
- Public, available, supported simple products add quantity one through the
  existing protected WooCommerce transport. Other products keep product links.
- Selected IDs and category/attribute matches work with an empty basket.
- Product activity records visible cards, product-page clicks and accepted
  additions. Showing the result remains the quiz's only headline Conversion.
- Product observations and addition outcomes survive result revisits. Leaving or
  closing a result stops reads/observers; late additions still refresh the cart.
- The editor has a short action explanation and an explicit simulation in
  Preview & test. It never changes a real basket or records product activity.
- Local coffee-finder demo is published with cart buttons enabled. Its existing
  visitor basket was not changed by this work.

## Reproduction

Use Node 22 for builds and budget checks. Run `npm run build`, then
`bash bin/build.sh all`. Extract the Free and Elite ZIPs into
`/tmp/wconvert-quiz-installed`. Keep the prior committed build's stage at
`/tmp/wconvert-quiz-baseline/stage` (the recorded baseline is `7129f63`).

Run `tools/visual-tests/recommendations-spike/server.mjs` with:

- `WCONVERT_TEST_CORE=/tmp/wconvert-quiz-installed/wconvert`
- `WCONVERT_TEST_PRO=/tmp/wconvert-quiz-installed/wconvert-pro`
- `WCONVERT_WOO_DIR` pointing at an extracted official WooCommerce plugin
- `WCONVERT_TEST_WP` and `WCONVERT_TEST_PHP` selecting the matrix row

Then run `check-quiz-products.mjs`, `check-quiz-package-cycle.mjs` and
`check-quiz-assets.mjs` from that directory's scripts using `node` from the repo
root. The cycle script swaps only the named disposable extracted directories
and restores the candidate in `finally`. Fixture endpoints must never be
installed on a merchant site. Start a fresh disposable server for each matrix
row. The older result-filter suite deletes a fixture term, so run it last.

## Limits and release handoff

These are engineering checks and our design judgment, not merchant research or
sales-uplift evidence. No production load, external cache proxy, arbitrary
extension/theme, or real-user usability claim is made. No public release, tag,
push or external message was sent.

The browser tool can operate the editor preview but cannot activate controls
inside the live storefront's closed shadow root. Public loading was visually
checked; cart operations were verified through real Woo HTTP requests and the
runtime tests, not a claimed end-to-end storefront browser click. One manual
storefront pass (desktop/phone, click Add to cart, check native cart) remains part
of staging review. Do not repeat the full automated suite without a new change.

Branch review covered published-result selection, cart operation/session binding,
late outcomes and result cleanup, conversion separation, capability/dependency
gates, transfer behavior, and the recorded package evidence. No blocking code
issues were found in this review; stale completion notes in the plan were corrected.

Next: perform that staging storefront pass, then follow the existing Free/Pro
release gates, including PR review and required CI. Real-user recruitment is not a
blocker for continued development; usability and business outcomes remain
unmeasured until there are users.
