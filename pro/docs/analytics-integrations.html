Measure your WConvert campaigns in GA4

WConvert sends campaign activity through the Google tag or Google Tag Manager already installed on your website. It does not install a tracker. Choose one route in Settings → Integrations. Native WConvert statistics continue independently.

Existing Google tag

  1. Find your web stream's Measurement ID in GA Admin → Data streams (starts with G-).
  2. Select Existing Google tag and enter that ID. The same stream must already be configured on your website, for example by Site Kit.
  3. Choose consent handling, enable the integration and save. Clear any additional page or CDN cache.
  4. Test on a page containing a published campaign. Having a gtag function only proves a local handoff is possible; verify receipt in GA.

Google Tag Manager recipe

Use a test workspace and property first. WConvert pushes namespaced events into the existing data layer; it does not create or publish a GTM tag.

  1. Select Google Tag Manager in WConvert. Use dataLayer unless your container uses another name.
  2. Create a Custom Event trigger with regular-expression matching: 
    ^wconvert\.(impression|lead_accepted|campaign_converted|dismissed|test)$
  3. Create Data Layer Variables (Version 2) for wconvert.ga_event, wconvert.debug_mode and each wconvert. field below.
  4. Create a GA4 Event tag targeting your existing Google tag/web stream. Set Event Name to the variable for wconvert.ga_event. Add the parameters below using the corresponding variables. Set debug_mode from wconvert.debug_mode.
  5. Attach the custom-event trigger. Review consent behavior with the consent manager and GTM consent overview. Google tags have built-in consent checks; additional consent requirements can prevent firing entirely. WConvert never sets or grants consent.
  6. Preview the container, verify one tag firing per WConvert event, inspect the destination stream, and publish the container when verified.

WConvert resets optional values to null on every data-layer push. This prevents the previous lead's capture role appearing on the next impression or test event. Keep the trigger narrow. Do not fire a second generic form tag for the same WConvert accepted lead.

Consent and privacy

The default WP Consent API mode requires an initialized consent manager exposing the statistics category. Unknown or denied permission withholds events. Service-specific denial for google-analytics is also respected where available. Consent is checked on every event. Events withheld before consent are not replayed.

The alternative “Existing Google tag / GTM manages consent” explicitly delegates collection to your installed tracking configuration. WConvert cannot verify consent in this mode. Advanced Google Consent Mode may send cookieless requests when storage is denied. Check your configuration against your site's requirements.

WConvert sends only campaign metadata: never form answers, email addresses, phone numbers, lead IDs or destination credentials. Public labels are visible to visitors and your analytics provider; use no personal information. The existing Google tag can collect its own standard page and session information, subject to your configuration. Update your privacy notice accordingly.

Event meanings

EventWhen it happens
wconvert_impressionAn overlay appears or an inline campaign enters the viewport. A reminder alone is not an impression.
generate_leadThe browser receives the first accepted lead acknowledgement for a mounted journey. Validation errors, unconfirmed requests and later optional SMS steps do not create another lead event. Destination delivery failure does not undo the accepted lead.
wconvert_conversionA click-driven campaign converts or a quiz reaches its result. Capture-driven campaigns use generate_lead instead. Quiz capture carries capture_role=secondary; completion and capture are different outcomes.
wconvert_dismissA deliberate dismissal, if enabled. Expiry, eligibility changes and closing after success are not dismissals.
wconvert_testA manager explicitly sends a synthetic diagnostic event; it contains no campaign identity. Never mark this as a key event.

Campaign controls

In campaign details choose Use site setting or Off for this campaign, and optionally supply a public label. Save and publish to apply. Private campaign names are not exported. A/B variants share family preferences and export distinct optin IDs. Promotion preserves inherited preferences, with published and draft changes separate. Duplicate campaigns reset the custom label.

Test without counting a real lead

Open Settings → Integrations → Test and verify while logged in as a campaign manager. Choose a page with a published campaign. The diagnostic panel observes activity locally and automatically closes after ten minutes. Routine campaign events are withheld on this diagnostic page. “Send synthetic test event” is a separate, explicit action: use a dedicated test stream with the direct route, or a test GTM workspace/property. Consent still applies.

“Handed off” means the existing JavaScript function or data layer accepted the call. It does not prove delivery to Google. Check Tag Assistant and GA DebugView or Realtime. A blocker, delayed tag, missing container configuration or network failure can prevent delivery. Tracking failures never prevent the campaign from working. There is no retry queue.

Routine export is off on WordPress non-production environments and for logged-in campaign managers by default. Ordinary logged-in customers remain eligible. Copying settings to another site URL disables routine export until the administrator reviews and saves the settings there. A clone must also use the correct WordPress environment type.

Useful reports

  1. Register event-scoped custom dimensions for wcv_campaign_id and the other fields you need. Start with campaign label and outcome; add optin ID for A/B analysis. Custom reports can take 24–48 hours after registration.
  2. To see which sources bring enquiries, create an exploration with Session source / medium and WConvert campaign label, using Event count and filtering Event name to generate_lead and a WConvert campaign ID. Use event counts when comparing accepted acts, not unique people.
  3. For a campaign funnel, compare impressions and accepted leads for the same campaign/outcome and period. Do not add quiz completions and secondary captures into one conversion rate.
  4. For an A/B test, break the shared campaign ID down by optin ID. Once a child is promoted its new campaign ID is its own ID; the old IDs remain meaningful historically.
  5. Mark the relevant event as a key event in GA if desired. Existing generate_lead key-event settings apply to WConvert too. For a WConvert-only key event, create a derived GA event with a WConvert parameter condition and mark that derived event instead; avoid marking both when it would double-count the same business outcome.

GA and native WConvert totals can differ because of consent, blockers, attribution, processing time, manager exclusions and lost acknowledgements. Existing site trackers may also measure generic form interactions; these are not accepted leads.
